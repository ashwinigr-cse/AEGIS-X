# CEM-Bench: Causal Experimentation and Memory Benchmark
## Scientific Evaluation Protocol & Metrics

**Benchmark Designation:** CEM-Bench (v1.0)  
**Objective:** Empirically quantify the performance differential between passive diagnostic agents and active, experiment-aware, memory-guided reliability scientists.

---

## 1. Experimental Configurations

Every benchmark scenario is evaluated across four distinct agent configurations under identical initial conditions:

| Config | Configuration Name | Agent Capabilities | Memory | Active Experimentation |
|---|---|---|---|---|
| **A** | *Zero-Memory Observational* | Passive telemetry analysis only. Suggests root cause from initial symptoms without testing. | None | Disabled |
| **B** | *Memory-Augmented Observational* | Retrieves past incidents using Hindsight semantic recall. Suggests root cause based on prior similarity without testing. | Hindsight (Recall) | Disabled |
| **C** | *Reflective Memory Observational* | Retrieves past incidents and executes Hindsight reflection synthesis. Still relies solely on passive observational inference. | Hindsight (Recall + Reflect) | Disabled |
| **D** | *Full AEGIS X (IGOM + Active EIG)* | Retrieves past experimental records, formulates competing hypotheses, calculates EIG, executes controlled interventions, and validates recovery. | Full Hindsight + Relational | Enabled (Active EIG) |

---

## 2. Benchmark Scenario Taxonomy

CEM-Bench defines reproducible failure scenarios with verifiable ground truth:

1. **Single Fault (SF):** Direct failure mode (e.g., downstream network latency between checkout and payment).
2. **Compound Fault (CF):** Concurrent faults (e.g., CPU throttling on cart + database connection pool starvation).
3. **Ambiguous Symptoms (AS):** Identical top-level 503 and latency symptoms generated by two observationally equivalent internal faults.
4. **Hidden Dependency (HD):** Failure propagating through an unmapped or transitive microservice dependency.
5. **Context Shift (CS):** Same symptom as a prior incident, but system configuration (pool size or replica count) has changed, invalidating the historical root cause.
6. **Contradictory Memory (CM):** Historical memory points to cause $X$, but current live telemetry contradicts $X$'s necessary preconditions.
7. **Failed Intervention (FI):** An experimental intervention fails to provoke expected behavior or causes unexpected side effects, requiring graceful rollback.
8. **Novel Incident (NI):** Zero prior experiences exist in memory; requires de novo exploration and hypothesis generation.
9. **Repeated Incident (RI):** Identical incident under identical conditions; tests whether memory enables rapid, minimal-step confirmation.
10. **Recovery Verification (RV):** Fault clears or rollback occurs; tests whether the system accurately distinguishes between persistent degradation vs. transient recovery.

## 3. Evaluation Metrics

For each run, the benchmark logs deterministic, non-simulated metrics:

1. **Root-Cause Identification Accuracy (RC-Acc):**
   $$\text{RC-Acc} = \mathbb{I}(H_{\text{diagnosed}} == H_{\text{ground\_truth}})$$
2. **False Conclusion Rate (FCR):**
   Percentage of investigations where a false hypothesis is declared root cause with high confidence.
3. **Number of Experiments Required ($N_E$):**
   The total number of interventions executed to reach diagnosis.
4. **Information Gained per Experiment ($\overline{\text{IG}}$):**
   Average entropy reduction $\Delta \mathbb{H}$ realized per completed experiment.
5. **Time to Verified Diagnosis (TTD):**
   Wall-clock duration from incident detection to post-experiment recovery verification.
6. **Memory Retrieval Relevance (MRR):**
   Overlap and applicability of recalled historical experiences against current incident context.
7. **Context Shift Robustness (CSR):**
   Diagnostic accuracy specifically on scenarios where a prior rule is invalid due to environmental shift.
